# OWN001: Definitions shared with a plan

## What it checks

Finds matching definition-key sets in a plan and another document in the same
language and configured domain. Defaults require five shared keys and
Jaccard similarity of at least 0.8.

## Basis

Heuristic. A plan and maintained documentation should not both own the same definition.

## Why it matters

Readers can mistake a planned field definition for the current interface.

## Example

In `guide.md`, when `reference.md` defines these same settings:

```markdown
---
kind: plan
---

- `host`: Server address.
- `port`: Listening port.
- `user`: Account name.
- `token`: Access token.
- `timeout`: Request timeout.
```

## Instead

```markdown
---
kind: plan
---

The implementation will use [the settings reference](reference.md#settings).
```

## Exceptions

Mentions in paragraphs, description columns, and code examples are not
definition keys. Pairs without a plan are outside this rule. A plan explicitly
declared canonical can outrank another document; generated files supply
ownership evidence but never receive diagnostics.

## Inputs

Only leading inline-code keys in described list items and inline-code keys
in table first columns are compared. Unlike `DUP001`, identifiers in the
descriptions do not contribute. Ownership and ties follow `DUP001`.

## Configuration

Enable preview and select `OWN001`. `[lint.dup] min-identifiers` and
`min-jaccard` control the thresholds. Declare a canonical document only when
it owns the shared definitions.
