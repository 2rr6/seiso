# M2 development and evaluation

Recorded on 2026-09-28. Functional development and natural diagnostic review
are complete. Performance acceptance remains open until the absolute gates
pass on the standard Linux CI runner.

## Delivered behavior

Checks build the full workspace index before applying report scope. Cross-file
reports include affected origins when a selected target changes. Configuration,
kind, domains, path existence, and anchor resolution are refreshed each run.
Generated documents can own content and supply targets without receiving
diagnostics. Comparisons remain pairwise and respect language and domain.

The content cache stores validated parse facts with checksums and atomic
writes. Equal content can share immutable models within a process. Continuous
source mappings represent exact byte ranges compactly; escapes and entities
retain their original syntax ranges. Bounded workers load documents while
sorted reports preserve deterministic order.

SUP002 offers safe edits only for confirmed unused codes. Mixed declarations
retain active, disabled, invalid, or undetermined codes. Incomplete checks
block writes. The CLI also exposes statistics, SARIF, GitHub annotations, and
`index --dump`; see the [checking guide](../checking.md).

## Natural diagnostic evidence

The [frozen run](../../corpus/results/m2/natural-v1/run.json) checks the same
1,953 documents and original Git inventories used for M1. Reversing repository,
document, and inventory order yields byte-identical output. All 3,909 existing
M1 diagnoses retain their complete diagnostic objects. M2 adds 571 diagnoses.

The [precision report](../../corpus/results/m2/natural-v1/summary.json) records
every new diagnosis, including tuning/holdout, language, kind, unknown judgments,
and annotation provenance. These are agent labels; no human labeling is
claimed. OWN002 has separate author review and independent agent review, with
matching decisions and no double counting.

The independent link oracle confirms the GitHub-style physical assertions,
but many original sites supply explicit renderer-specific anchors such as
`{#custom-id}`. Those diagnoses are false positives for the source document's
actual use. Ownership false positives include page-local imports, provider
installation templates, prerequisites, and ordinary repeated introductions.
Tuning contains additional unresolved renderer and catalog cases; the report
retains them as uncertain.

All new rules remain preview. Zero natural samples do not validate precision,
and no rule, threshold, kind profile, or corpus input was changed in response
to these holdout judgments. DUP/OWN precision reports satisfy the reporting
requirement without establishing promotion eligibility.

## Regression and CI coverage

Local verification passed 190 Rust tests on Windows, 191 on Linux, and
47 Python tests. Rustfmt, strict Clippy, and workflow syntax checks passed.
Both the Windows wheel and the source distribution were installed in clean
environments and exercised with index inspection, statistics, rule help,
and safe fixes. The repository's stable and preview checks both returned
success. These checks did not publish a package.

The [CLI matrix](../../crates/seiso_cli/tests/m2.rs) covers cache equality,
target edits and deletion, report filtering, stdin overlays, generated and
excluded targets, path moves, mixed suppression fixes, incomplete inputs,
statistics, machine output, and parallel reads. Windows path aliases and
symlink boundaries have dedicated cases. Rule documentation examples and
pairwise ownership behavior have executable fixtures and snapshots.

The [evaluation workflow](../../.github/workflows/evaluation.yml) runs frozen
corpus comparisons, retains complete artifacts, and reports changes on
same-repository PRs. The [baseline decision](m2-baseline-decision.md) records
the approved transition from M1's selected-file hook to M2's full workspace
semantics. Absolute performance targets remain unchanged.

The [local performance receipt](../../corpus/results/m2/performance/receipt.json)
binds the fixed workload, executable, script, and raw measurements. In seven
uncontended local WSL samples, median cold, warm, and hook times were
182.2 ms, 35.9 ms, and 34.4 ms respectively. All local absolute targets passed;
these results are separate from the required standard-runner CI acceptance.

Preview timing is separate from the stable-rule gates. The deliberately dense
benchmark contains many genuinely similar paragraphs. Complete related-location
output can become very large even after candidate filtering; measured preview
timeouts are retained as a limitation rather than counted as a passing latency
result.
