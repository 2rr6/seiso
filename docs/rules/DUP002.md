# DUP002: Restatement followed by a link

## What it checks

Finds sections that end with a local link and share at least five distinct
inline-code identifiers with its target. At least 80% of the source section's
identifiers must appear in that target.
A link without a fragment compares against the complete target document.

## Basis

Heuristic. A trailing reference can reveal that the preceding text restates its target.

## Why it matters

Restating a reference before linking to it creates another copy to maintain.

## Example

In `guide.md`, when the linked reference defines the five settings:

```markdown
---
kind: howto
---

## Settings

Configure `host`, `port`, `user`, `token`, and `timeout` for the connection.

See [the settings reference](reference.md#settings).
```

## Instead

```markdown
---
kind: howto
---

## Settings

See [the settings reference](reference.md#settings).
```

## Exceptions

Child sections are evaluated separately. Text after the link, except sentence
punctuation and whitespace, prevents the trailing-link match. External links,
images, same-file links, different languages, and different domains are excluded.
Undetermined targets leave the rule incomplete for suppression evaluation.

## Inputs

Section boundaries, inline-code identifiers, resolved links, and target anchors.
Ownership follows `DUP001`; the lower-ranked side receives the diagnostic even
when it is the link target. Equal highest-ranked owners use `OWN002`.

## Configuration

Enable preview and select `DUP002`. `[lint.dup] min-identifiers` sets the minimum
shared identifier count; `min-jaccard` sets the minimum source containment ratio
for this rule. The denominator is the source section's identifier count.
